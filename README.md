# TRPGシナリオ コピー支援

TRPGセッション中に、シナリオ本文から必要な行を手軽にコピーするための静的Webアプリです。

シナリオ本文を行単位で表示し、クリックやドラッグでコピーできます。
PC名などの文字列置換や、コピー用の改行編集にも対応しています。

入力した本文の処理はブラウザ内で完結し、外部サーバーへの送信は行いません。

## 主な機能

### 1. 行単位でのコピー

- 行をクリックすると、その行のテキストをコピー
- 複数行をドラッグすると、選択範囲をまとめてコピー
- コピー画面の本文文字サイズを7段階（12〜24px）で調整可能

### 2. 文字列の置換

PC名など、シナリオごとに読み替えたい文字列を任意の文字列に置換できます。

例えば、シナリオ本文中のキャラクター名を `{PC}` のような変数形式に変換できます。

- 複数の置換ルールを登録可能
- ルールごとにON/OFFを切り替え可能
- 置換対象のハイライトをクリックして、特定の箇所だけ置換から除外可能
- 除外した箇所は個別に置換対象へ戻すことも可能

### 3. コピー画面での改行編集

元のシナリオ本文を変更せず、コピー画面上で改行を追加・削除できます。

- 任意の位置で改行を追加
- 行間の改行を削除して前後の行を結合
- 編集後の行をそのままクリック・ドラッグでコピー可能

### 4. 置換設定の保存・読み込み

置換ルールをJSONファイルとして書き出し、別の機会に再利用できます。

- 置換ルールの保存・読み込み
- 読み込み時に既存設定との置き換え・追加を選択可能
- 必要に応じて、個別の置換除外や改行編集の状態も保存可能

## 使い方

### 1. アプリを開く

`index.html` をブラウザで開きます。

依存関係のインストールやビルドは不要です。

### 2. シナリオ本文を入力する

「入力・設定」タブで、以下のいずれかの方法で本文を読み込みます。

- テキストエリアに直接入力・貼り付け
- UTF-8形式の `.txt` ファイルを読み込み

### 3. 必要に応じて置換ルールを設定する

「文字列の置換」を開き、置換機能を有効にします。

「ルール追加」から、置換前・置換後の文字列を登録してください。

### 4. コピーする

「コピー」タブに移動すると、本文が行単位で表示されます。

| 操作 | 動作 |
| --- | --- |
| 行をクリック | 1行をコピー |
| 行をドラッグ | 複数行をまとめてコピー |
| 置換ハイライトをクリック | その箇所の置換を除外・再適用 |
| 本文中で右クリック | 指定位置に改行を追加 |
| 行間をダブルクリック | 改行を削除して行を結合 |
| A− / A+ | 本文の文字サイズを変更 |

詳しい操作方法は、画面右上の「? 使い方」からも確認できます。

## データの保存・取り扱い

### ブラウザ内での処理

シナリオ本文の読み込み・置換・コピー処理はブラウザ内で行います。

入力したシナリオ本文を外部サーバーへ送信する機能はありません。

### ブラウザへの自動保存

以下の情報は、ブラウザの `localStorage` に保存されます。

- 置換ルールとその設定
- コピー画面の文字サイズ

シナリオ本文そのものや、個別の置換除外・改行編集の状態は、自動保存されません。

### JSONファイルへの保存

置換設定はJSON形式で書き出せます。

「この本文での編集状態も保存」を選択すると、以下の情報も保存対象になります。

- 個別に置換を除外した箇所
- コピー画面で追加・削除した改行

保存した編集状態は、同じ本文に対して設定JSONを「現在の設定と置き換える」で読み込んだ場合に復元できます。

「現在の設定に追加する」で読み込んだ場合、編集状態は復元されません。

なお、設定JSONにシナリオ本文そのものは含まれません。

## 公開・実行環境

HTML・CSS・JavaScriptで構成された静的Webアプリです。

- 外部ライブラリへの依存なし
- ビルド不要
- GitHub Pagesで公開可能

GitHub Pagesを利用する場合は、リポジトリ直下を公開対象に設定することで動作します。

## 技術仕様

### 改行編集の管理

改行編集は、元テキストを直接変更せず、コピー画面上の表示状態として管理します。

- 改行の追加・削除は元テキストに反映されない
- 本文が変更された場合、改行編集はリセットされる
- 同じ本文への入力方式切り替えでは編集状態を保持する
- 改行コードはCRLF・CRをLFに正規化して比較する

### 改行編集のJSON形式

設定JSON（v1）の `individualState` に、以下の任意項目を追加できます。

```json
{
  "insertedBreaks": [
    {
      "lineId": "line-0",
      "offset": 2
    }
  ],
  "removedLineBreaks": [
    "line-1"
  ]
}
```

各項目の意味は以下のとおりです。

- `lineId`：解析時に割り当てられる元行ID
- `offset`：対象行の置換後テキストにおけるUTF-16オフセット
- `insertedBreaks`：追加した改行の位置
- `removedLineBreaks`：削除した改行の直前にあたる元行ID

改行の追加位置は、置換ルールの変更や個別除外の切り替え後も数値位置として保持します。
ただし、現在の置換結果の長さを超える位置には適用しません。

編集状態の復元には本文のフィンガープリントを使用します。
本文が一致する場合のみ復元し、追加モードでの読み込みでは復元しません。

置換ルールのみを保存したJSONには改行編集情報は含まれず、従来のv1形式との互換性も維持しています。

## テスト

Node.jsの標準テストランナーを使用しています。

リポジトリ直下で以下を実行します。

```sh
node --test
```

主なテストファイルは以下のとおりです。

| ファイル | 主な検証対象 |
| --- | --- |
| `lineBreaks.test.js` | 改行の追加・削除、複合操作、コピー処理、JSON互換性 |
| `replacementSettings.test.js` | 置換設定の保存・読み込みに関する処理 |
| `copyFontSize.test.js` | 文字サイズの変更・保持、コピー処理への影響 |
